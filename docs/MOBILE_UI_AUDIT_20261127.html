高信息密度问题
关键测试发现（工具链 bug，已修复）：cli_device.mjs 原来取 /proc/net/unix 第一个 WebView socket，连到了手机上另一个 App（cn.kexie.kxyj）的 WebView，导致冒烟测试卡死 5 分钟。已改为按应用 PID 精确匹配 socket（提交 d1bdbb6）。另外 __FM_TEST__.tap() 使用 1280×720 设计坐标，不是 1600×900 屏幕坐标——此前用屏幕坐标导致大量"误触 0% 命中"是假象，非游戏 bug。

总体判断

没有致命布局 bug：所有页面无黑屏、无控件溢出屏幕、无元素重叠到不可用。核心矛盾是信息密度过高 + 小字号——这是 FM 类游戏的必然取舍，但在 1600×900 横屏手机上，大量 10~12px 的说明文字和数值标签确实偏小。此前已落地的 FONT 语义 token / drawStatBar 等改造在真机上生效，但仍有若干页面未完全覆盖。

本轮新发现的适配问题

赛后复盘：底部主 CTA 被成就 Toast 覆盖 P1

  • 「下一步：领取赛后肉鸽奖励」与「解锁成就：零封铁闸 (+15pt)」Toast 落在同一行
  • Toast 描边压在按钮上边框，观感像按钮被切了一刀
  • 建议：Toast 底距抬高到 96px 以上，或在有底部 CTA 的页面把 Toast 移到顶部广播条

新手引导气泡压住底部状态栏 P1

  • draft 步气泡 + 老恩师立绘占据底部 96px，正好盖住「当前 11 人（已抽核心 0/9）」状态条
  • 立绘左缘还切掉了状态条首字，读起来是「当前 11 人」缺半边
  • 建议：气泡左移或用 8px 网格重新排布，把立绘从状态条区域移开

比赛日开球过场：VS 圆环压住提示文案 P2

  • 「点击任意位置或按 空格/回车 立即开哨」正好穿过客队卡右侧 VS 圆环
  • 中文字被蓝色圆环切断，读起来断句
  • 建议：提示文案下移 24px，或改为在两张队伍卡下方居中

赛季收官页：顶部副标题与底部继承文案被压 P2

  • 标题下方「第N赛季 · …」副标题被「赛季个人荣誉殿堂」面板上沿切掉
  • 底部「原承逸已继承梅利纳衣钵…」与主按钮行底边重叠
  • 建议：右侧内容整体下移 12px，底部说明行改为与按钮同基线

文本输入弹窗：4 按钮同行偏挤 P2

  • 随机队名 / 清空 / 取消 / 确认 四颗按钮挤在 440px 宽弹窗内
  • 每颗约 100×36 设计像素，手机上实际约 84×30
  • 建议：随机队名与清空降级为图标，或把「清空」并入输入框尾部

序章比赛强制教程存在「时钟冻结」体验风险 P2

  • 47'/73' 要打出指定牌、80' 要开换人面板换老队长、89' 要放绝杀技
  • 每一步不完成，比赛时钟就完全停住（不是慢放），且无超时兜底
  • 提示横幅有指引，但玩家若误触别处会以为卡死
  • 建议：保留强制节奏，但加「30 秒未操作 → 高亮目标 + 震动/音效提醒」

工具链：本轮补齐的测试能力

__FM_TEST__ 新增三个接口（仅 ?e2e=1 / localStorage.fm_e2e=1 时挂载，线上玩家不可见）：
  • getHits() → 当前帧所有可点热区矩形。Canvas 没有 DOM 定位器，这是唯一能枚举「这一页有哪些可点区域」的途径，也是本次能定位「进入比赛日按钮中心其实是 (974,34)」的原因。
  • getModals() → 当前打开的弹窗名列表，用于断言「弹窗确实开了 / 确实关了」，避免用亮度差分猜测。
  • getTutorial() → 新手引导进度，判断遮罩是否应该出现。
