FM-League 移动端适配审查报告

真机：vivo V2227A / Android 16 / 1600×900 横屏（设计 1280×720，1.25×）· 版本 0.1.0+c5e95b8ae8b4 · 2026-11-27

0崩溃/黑屏
高信息密度问题
关键测试发现（工具链 bug，已修复）：cli_device.mjs 原来取 /proc/net/unix 第一个 WebView socket，连到了手机上另一个 App（cn.kexie.kxyj）的 WebView，导致冒烟测试卡死 5 分钟。已改为按应用 PID 精确匹配 socket（提交 d1bdbb6）。另外 __FM_TEST__.tap() 使用 1280×720 设计坐标，不是 1600×900 屏幕坐标——此前用屏幕坐标导致大量"误触 0% 命中"是假象，非游戏 bug。

总体判断

没有致命布局 bug：所有页面无黑屏、无控件溢出屏幕、无元素重叠到不可用。核心矛盾是信息密度过高 + 小字号——这是 FM 类游戏的必然取舍，但在 1600×900 横屏手机上，大量 10~12px 的说明文字和数值标签确实偏小。此前已落地的 FONT 语义 token / drawStatBar 等改造在真机上生效，但仍有若干页面未完全覆盖。

逐页问题清单

赛季门户 P1

  • "赛季备战三步骤"说明文字偏小，第三行接近 11px 视觉
  • 左侧引导卡片（青训学院/转会市场/神秘经纪人）副标题拥挤
  • 右侧"俱乐部赛季脉络与词条"大段说明字号小、行距紧
  • 顶部"距 26 人注册还差 6 人"提示条信息量大

联赛赛程 P2

  • 积分榜 10 列信息在 1600 宽下可控，但净胜球/积分列字号偏小
  • 赛程列表"第1轮·下段"等徽标文字小
  • 近期已赛结果为空时占位文字居中，可读性尚可
  • 整体为表格型布局，横屏友好，无溢出

战术与阵容 P1

  • 球场球员卡片（如 43/55、毛熙阳）多行信息密集，底部绿色体力条+百分比重叠感强
  • 替补席卡片右侧"最佳首发/断技"小标签字号极小
  • 顶部战术条 "攻62 / 中48 / 防48" 与方案页签混排
  • 球员卡在球场上间距紧凑，接近重叠边缘

引援中心（阵容名单） P0

  • 信息密度最高：3×3 球员卡片，每卡含名字/年龄/CA-PA/5 项属性/习惯/0场0球
  • 球员卡内 5 项属性数字（如 72/20/43/88/76）字号约 10px，过小
  • 左侧榜单 10 行 + 卡片区，双栏同时高密度
  • 顶部"急需补全"等建议文字换行拥挤
  • 页签（一队名单/青训学院/转会市场/经纪人）文字偏小

Meta 星盘 P1

  • 星盘节点标签（如"四后卫"「三中卫」「4-3-3」）字号小，深色背景对比度不足
  • 节点图标密集，中心区 9 个图标间距小
  • 顶部"92 PASSIVES · 122 DIRECTIVES · 59 SKILLS"说明文字偏小
  • 新手引导横条文字小但位置合理

荣誉/名人堂 P2

  • 左侧"执教生涯统计"4 个数据块留白充足

  • 整体是本次审查中最清爽的页面

比赛日实时 P1

  • 底部指挥卡 4 张，卡面"稳稳拼图 · 点击替换"文字小
  • 顶部比分/球队名区域清晰，实时战报左栏文字密度高
